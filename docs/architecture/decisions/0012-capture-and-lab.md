# 0012: Capture and Lab, internal tools for training data

- Status: Accepted
- Date: 2026-11-03
- Builds on: [0001](0001-on-device-data.md), [0011](0011-snap-to-score.md)

## Context

Fine-tuning the snap-to-score model (ADR 0011, plan S4) needs many hundreds of labelled visits across angles, distances, lighting and dart groupings, with a verification set that never leaks into training. Collecting them through Ton Up's own "Keep photos" setting and copying folders through the Files app is slow, and every labelling mistake goes straight into the dataset. Starting training and verification runs, and comparing and keeping models, is done by hand from the command line.

This tooling is for Neil's own board and photos. It has to stay separate from the Olympus infrastructure and be light enough to run on the M1 Pro laptop that also trains the model (Docker on macOS can't reach the Mac's GPU, so training runs natively).

## Decision

1. **Ton Up Capture:** an internal iPhone app built from this repo as a second variant of the Expo project (`APP_VARIANT=capture`): its own name, icon, bundle ID (`app.tonup.ios.capture`) and routes directory (`src/capture-app`), sharing the domain code, UI, theme and `dart-vision` module. It is installed from Xcode and never submitted to the App Store.
2. **Labelling is values, then tips:** the player enters what the darts scored, marks the board, then taps each tip; every tap is scored through the shared geometry and must match its entered value (or be flagged). Values alone are kept only as verification data, since a keypoint model can't learn from them.
3. **Ton Up Lab:** a single-user web app in `lab/` (Next.js with Ant Design, SQLite through Drizzle), run on the laptop. It stores captures, assigns splits, snapshots datasets, runs training and verification as child processes of the `ml/` Python environment, and keeps a model registry. No Postgres, nginx, Docker, certificates or other Olympus services.
4. **Plain HTTP on the local network, no auth:** Capture uploads to Lab at `http://<laptop>.local:3100`. Lab listens on localhost unless started with the LAN script, so it isn't open on networks away from home.
5. **Splits are per session and permanent:** a session is assigned train, val or test (80/10/10 by hash) when it arrives and never moves; the label files carry the split, and `ml/` uses it. The test split is the verification set and is never trained on.
6. **Ton Up itself is unchanged:** the shipping app keeps no network code (ADR 0001); the capture routes and upload code are outside its routes directory and so outside its bundle. A model reaches Ton Up only by being copied into `modules/dart-vision/ios/Models` and shipped in a build.

## Consequences

- Two iOS variants share one `ios/` folder generated by prebuild, so switching between them means a clean prebuild (scripts in `package.json`).
- `lab/` is its own pnpm project with its own lockfile, outside the Expo app's hoisted `node_modules`, and is excluded from the app's TypeScript, ESLint, Jest and Metro.
- `ml/` gains a metrics file per epoch, per-image evaluation output, DeepDarts sampling for fine-tunes, and reading the split and session from capture labels.
- The capture label format gains fields (session, split, entered values, flags); `tonup_ml` ignores those it doesn't use, so Ton Up's own captures still load.
